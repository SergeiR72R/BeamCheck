# BeamCheck — нагрузки от стоек лесов на балку (PERI CAD)

Модуль для PERI CAD. Автоматически собирает нагрузку от стоек строительных лесов,
стоящих на балке: полезная нагрузка по классу EN 12811-1 и вес деков на каждом ярусе,
плюс вес самих стоек, леджеров, диагоналей и ограждений. Результат вставляется в чертёж
как 2D-схема балки с точками нагрузки, цепочкой размеров и таблицей.

| Платформа | Сборка | .NET |
|---|---|---|
| PERI CAD 24 (на AutoCAD 2021–2024) | `BeamCheck.Acad.dll` | .NET Framework 4.8 |
| PERI CAD на BricsCAD V25 | `BeamCheck.Bcad.dll` (net48) | .NET Framework 4.8 |
| PERI CAD на BricsCAD V26+ | `BeamCheck.Bcad.dll` (net8) | .NET 8, x64 |

Весь расчёт живёт в `BeamCheck.Core` и не зависит от CAD. Код команд, отрисовки и диалога
(`BeamCheck.Cad.Shared`) общий; различаются только `using` в блоках `#if BRICSCAD`.

## Команды

| Команда | Что делает |
|---|---|
| `BEAMLOAD` | Основная команда: выбрать балку → выбрать стойки → диалог → вставить схему и таблицу |
| `PERIDUMP` | Диагностика: выгружает в текстовый файл всё, что модуль «видит» в выбранных объектах |
| `BEAMLOADSETTINGS` | Открывает файл настроек `%APPDATA%\BeamCheck\BeamCheck.settings.json` |
| `SPINDELLOAD` | Максимальная нагрузка в каждом шпинделе (Fuß-/Kopfspindel, UJB) всего чертежа — тем же расчётом, что `BEAMLOAD` (см. [`docs/SPINDLELOAD.md`](docs/SPINDLELOAD.md)) |
| `SPINDELDUMP` | Диагностика: распознаётся ли выбранная деталь как шпиндель |
| `SPINDELSETTINGS` | Открывает настройки шпинделей `%APPDATA%\BeamCheck\BeamCheck.Spindle.settings.json` |

### Порядок работы `BEAMLOAD`
1. **Выбрать балку.** Её ось и длина определяются по геометрии блока.
2. **Выбрать стойки.** Можно рамкой, и достаточно **любой секции** стойки: модуль сам
   соберёт всю колонну (все секции 0,5–2 м на той же оси выше балки).
3. Модуль ищет вокруг стоек леджеры и деки и строит путь нагрузки:
   *дек → 2 опорных леджера (по ½) → концы леджера (по правилу рычага) → стойки*.
   В обычном пролёте стойка получает ¼ каждого прилегающего дека. Отсутствующие деки,
   крайние и неравные пролёты учитываются автоматически.
4. **Диалог:**
   - класс нагрузки 1–6;
   - режим ярусов: «расчётный ярус 100 % + один соседний 50 %» (EN 12811-1) или «все ярусы 100 %»;
     коэффициент каждого яруса можно поправить вручную;
   - γG / γQ, отсчёт от другого конца балки, показывать Fk или Fd;
   - таблица результатов по стойкам с разбивкой по ярусам и список предупреждений;
   - **«Показать в модели»** подсвечивает всё, что попало в расчёт;
   - **«Исключить объекты…» / «Добавить объекты…»** — ручная правка
     (при добавлении можно указать, что объект — дек, леджер или стойка);
   - экспорт CSV.
5. **«Вставить в чертёж»** → указать точку. На слой `BEAMLOAD` вставляются схема балки,
   стрелки с нагрузками в кН, цепочка размеров (от края до каждой нагрузки, между нагрузками,
   общий размер) и таблица. Всё объединено в группу.

## Веса деталей
PERI CAD не хранит вес в свойствах детали, поэтому он задаётся таблицей артикулов:
`%APPDATA%\BeamCheck\BeamCheck.weights.csv` (создаётся при первом запуске из шаблона).
Колонки: `Article;WeightKg;Name`. В поставку уже включены 34 артикула UP Flex из Stückliste
PERI CAD 24 (стойки UVR/UVH, леджеры UH/UHV Plus, стальные деки UDG). Остальные артикулы
добавьте из спецификации PERI; строки без веса игнорируются. Для остальных деталей применяются запасные значения на метр / м² из настроек,
и модуль предупреждает об этом в диалоге.

## Нагрузка по всем ярусам и через вышестоящие балки
- **Live load** по умолчанию прикладывается **на одном ярусе — самом нагруженном** (работы ведутся
  на одном ярусе): выбирается ярус с наибольшей площадью деков на выбранных стойках. Остальные
  режимы переключаются в диалоге: «все ярусы 100 %» и «один ярус 100 % + один соседний 50 %»
  (EN 12811-1); коэффициент любого яруса можно поправить вручную.
  **Self weight** (деки, леджеры, секции стоек до самого верха, верхние балки) учитывается
  по всем ярусам всегда.
- Итоговая строка (диалог и таблица на чертеже): `площадь | live load | self weight load | total load`,
  где площадь — общая площадь деков всех ярусов до верха стойки (площадь под live load указана в примечании), total = self weight + live load (нормативные).
- Если на выбранные стойки опирается **вышестоящая балка**, на которой стоят другие стойки
  (со своими ярусами до самого верха), их нагрузка передаётся вниз:
  стойка на балке → опоры балки по правилу рычага (каждый пролёт как простая балка, консоль
  по статике соседнего пролёта) → выбранные стойки → нижняя балка. Вес самой верхней балки
  распределяется так же. Цепочка может быть многоэтажной (балка на стойках, стоящих на балке…).
  Опоры, которые вы не выбрали, забирают свою долю; в таблице она не учитывается.
- Верхние балки можно указать в `BEAMLOAD` (второй запрос выбора) или оставить автоматическому
  поиску: он узнаёт балки по названию (правило `Beam` в настройках) и по положению: балка лежит
  на верхушке или в голове найденной стойки. Профиль, который правила названий не знают
  (например, DC 52×120), но через который проходит выбранная стойка не у его концов
  (леджеры стыкуются со стойками только концами), тоже считается верхней балкой. Короткая стойка,
  стоящая на балке (её голова чуть ниже низа балки), опорой балки не считается.
  Вес верхней балки берите из `BeamCheck.weights.csv`.
- **Проверяемым элементом может быть и леджер.** Что выбрано (леджер или балка), модуль определяет сам:
  по названию/артикулу детали, а без них по форме. Дальше всё считается по той же схеме (стойки на нём, их
  ярусы до верха, верхние балки). Деки, лежащие прямо на леджере, добавляются отдельными точками
  D1, D2… (по половине веса и полезной нагрузки дека на каждую); в диалоге это галочка
  «Деки, лежащие на самом элементе».
- **Консоли (UCM …).** Консоль закреплена на стойке (корень) и работает как консольная балка: деки на ней и
  стойка на её конце (с её ярусами, леджерами и консолями выше) передают нагрузку целиком в стойку корня,
  дальше по цепочке вниз до проверяемого элемента. Консоль находится по названию (`UCM`, `Konsole`), высота
  опирания дека берётся по её верхней планке (а не по штырю). Вес консоли — из таблицы весов или `ConsoleKgPerM`.
  Леджер, подсоединённый к консоли (к её концу или сбоку, допуск `ConsoleLedgerTolerance`, 10 мм), передаёт свой вес и нагрузку
  лежащих на нём деков на опорный стандарт консоли. Высота этажа в сводке — от верха проверяемой балки или леджера.
- **Интерфейс на немецком.** Диалог, запросы командной строки, предупреждения, таблица и схема в чертеже — на немецком.
- **«Im Modell zeigen…»**: учтённые детали подсвечиваются, дальше можно выбрать `Drehen` (3DORBIT — вращать камеру, выделение остаётся),
  `Isolieren` (ISOLATEOBJECTS — скрыть всё остальное), `Alles zeigen` (UNISOLATEOBJECTS), `Zoom` (на учтённые детали)
  или `Weiter` (вернуться в диалог). Перед вставкой схемы или при отмене изоляция снимается сама.
- **Пакетный режим `BEAMBATCH`** (без ручного выбора): выделить всю модель → модуль находит все балки (тип Beam: SRU, RCS… по названию/артикулу),
  называет их B-001, B-002… (по высоте, затем X, Y), для каждой сам находит стойки на ней и опоры под ней и считает нагрузки.
  Опора — стойка, на которой лежит балка; если стоек под балкой нет, она лежит на твёрдой плоской поверхности. Нагрузка каждой балки своя:
  сначала на верхнюю балку, потом через её опоры на нижнюю. Всё читается слева направо; расстояния — от левого края балки по цепочке, мм.
  Результат: Excel (`Übersicht` — все балки, `Positionen` — опоры и нагрузки с положением и расстоянием от предыдущей, `Abbildungen` — картинка профиля балки
  с нагрузками A, B…, опорами S1…, реакциями и цепочкой размеров), список балок с поиском и подписи B-xxx в модели (слой `BEAMCHECK_NAMEN`).
  Реакции опор — по правилу рычага для каждого пролёта вместе с собственным весом балки. Прогресс с оценкой оставшегося времени, можно прервать.
- **Navisworks (NWF/NWC из нашей модели):** данные PERI (артикул, handle) в Navisworks не сохраняются, поэтому балки ищутся по координатам:
  `BEAMBATCH` пишет `<чертёж>_Traeger_Ansichtspunkte.xml` — сохранённые виды, по одному на балку (имя B-001…), камера смотрит на балку сбоку и немного сверху.
  В Navisworks: «Gespeicherte Ansichtspunkte» → правый клик → «Ansichtspunkte importieren». Координаты равны координатам чертежа (файл в м, чертёж в мм).
  Формат и система координат камеры сверены с видами, экспортированными из Navisworks Simulate 2023. Центр балки (X, Y, Z) есть и в Excel.
- **`BEAMEXPORT`** (сервисная команда): тот же выбор, что в `BEAMLOAD` (балка, стандарты, верхние балки), без диалога; все учтённые в расчёте детали копируются в новый DWG рядом с чертежом (`<чертёж>_Lastermittlung_<балка>_<время>.dwg`, координаты сохраняются). То же есть кнопкой «In neue DWG kopieren…» в диалоге `BEAMLOAD` — копируется ровно то, что осталось после «Objekte ausschließen/hinzufügen». Копируется объект верхнего уровня целиком (деталь внутри блока-сборки идёт вместе с блоком).
  Кнопка «Rechenweg…» в диалоге `BEAMLOAD` пишет CSV с разбором расчёта: Gk по видам деталей (напрямую / через верхние балки), по этажам (площадь, Qk, вес) и по каждой передающей балке; суммы совпадают с таблицей диалога.
  Стойка, стоящая на пине (UH Zapfen / UHA Zapfen, `PinPattern`) посередине леджера, передаёт всю свою нагрузку на этот леджер в точке пина; леджер делит её на свои концы по рычажному правилу (как верхняя балка с двумя опорами). Rechenweg объясняет каждую площадь (настил, леджер, плечо d, доля ½·(1−d/L)) и каждое распределение по опорам (проценты и кН). Балки, лежащие на стойке на пине, находятся, как обычные верхние балки; верхние балки и леджеры с пинами ищутся поочерёдно до 4 кругов (цепочки балка → пин → леджер → балка).
  Допуски 5 см (по плану и по высоте) для всех подсоединений: конец леджера к консоли (`ConsoleLedgerTolerance`), конец леджера к другому леджеру через каплер UHA (`CouplerTolerance`, `LedgerOnLedgerHeight`), пин на леджере (`PinPlanTolerance`). Леджер, подсоединённый к консоли без стойки на ней, передаёт нагрузку на консоль и её стойку; к такому леджеру могут перпендикулярно крепиться другие леджеры (в т. ч. с пинами и стойками на них) — пропорционально положению каплера. Консоли ECM 50/75/100 распознаются как UCM.
  Риббон: вкладка «Berechnungssoftware» (панель «BeamCheck – Träger», кнопки BEAMLOAD/BEAMBATCH/BEAMFIND/BEAMEXPORT/Einstellungen) создаётся модулем при старте (`PeriRibbon.cs`; общий идентификатор вкладки — будущие модули добавляют в неё свои панели). Раздача через сетевую папку: `deploy/publish.ps1 -Share \\сервер\папка`, коллеги запускают `install.cmd` оттуда (см. `deploy/NETZWERK.md`).
  Nachweise балок (BEAMBATCH, лист «Nachweise» и столбцы «Profil / η max / maßgebend / Nachweis» в «Übersicht»): балка считается неразрезной на шарнирных опорах под нагрузками Fd и собственным весом × γG (`Proofs/BeamStatics.cs`). SRU (2×U120, ST_was_2024/00040): v, m, v-m, n-v-m по сечениям 4-4, 5-5, 2-2 — берётся худшее; RCS (2×U200 нетто, ST_kls_2016-00106): v, m, v-m с MV,y,Rd; GT 24 (MULTIFLEX): VRd 19,5 кН, MRd 10,5 кНм, на опорах Fm,Rd/Mm,Rd по случаям 1–4 (по умолчанию неблагоприятные 2/4, `Gt24FavourableDiagonals`); VT 20: VRd 16,5 кН, MRd 7,5 кНм, Rb,Rd 24 кН у конца / 33 кН при ≥ 45 см от конца. Крайняя опора считается торцевой при консоли ≤ `GirderEndSupportOverhang` (500 мм).
- **`BEAMFIND`**: список балок рядом с чертежом (`<имя>.beamcheck.json`, создаётся при `BEAMBATCH` после сохранения чертежа); по имени (B-014) или handle
  балка подсвечивается/приближается/изолируется, как в «Im Modell zeigen».
- В таблице результатов появляется колонка «в т.ч. с верх. балок», в диалоге —
  «Высота до Z» и число секций каждой колонки (чтобы видеть, до какой отметки стойка учтена).

## Стойка на головном шпинделе со смещением
Если следующая стойка смоделирована не точно над головным шпинделем (Kopfspindel), а **сбоку до 600 мм**
(`StackTransferPlanDistance`) или с **зазором по высоте до 600 мм** (`StackTransferHeight`), и её низ (шпиндель, опорная плита)
не стоит на балке, деке или пальце, вся её нагрузка передаётся в эту колонну. Колонна при этом не должна нести ничего другого
(если на её голове лежит балка, стойка относится к балке). Каждая такая передача указана в примечаниях и в Rechenweg
(«Versetzt auf dem Kopf»). Выключатель: `StackTransferEnabled`.
Для головных шпинделей (`HeadPartPattern`), на которых ничего не найдено, `BEAMLOAD` спрашивает
«Was steht darauf? [Wählen/Nichts/Keine weiteren]»: выбранная стойка передаёт всю нагрузку в эту колонну
(кнопка в диалоге «Was steht auf dem Kopf?…»).

## Как деки привязываются к леджерам
Дек опирается на леджер, если его опорный край лежит **не дальше 5 см** от оси леджера в плане и
по высоте отличается не более чем на **±5 см** от «нормальной посадки» над **верхней гранью леджера**
(высота берётся по габариту самой детали, поэтому усиленный, более высокий леджер несёт деки выше). Нормальную посадку модуль
измеряет по самой модели (медиана по декам, лежащим на леджерах), поэтому не важно, какой контур
PERI рисует для дека. Допуски: `DeckBearingTolerance` и `DeckHeightTolerance` в настройках.
Деки, которые не лежат на леджере в этом допуске, **всё равно считаются**: их опора привязывается к
ближайшему леджеру, идущему поперёк дека (флажок «Деки не на леджере — привязать к ближайшему, мм»
в диалоге; по умолчанию до 300 мм, `DeckSnapEnabled` / `DeckSnapDistance` в настройках). В окне
сообщается, сколько опор привязано и на какое расстояние отклонились. Деки, у которых ближайшего
леджера нет и в этом пределе, перечисляются с расстояниями.

**Леджер на леджере (соединитель UHA).** Поперечный леджер может одним концом висеть не на стойке, а
на другом леджере через UHA. Тогда нагрузка этого конца (деки, которые лежат на поперечном леджере,
и его вес) передаётся на опорный леджер по правилу рычага по положению узла и дальше на стойки на его
концах. Условия: леджеры пересекаются (не идут вдоль друг друга), верхние грани отличаются не более
чем на 25 см (`LedgerOnLedgerHeight`), конец лежит в пределах 12 см от оси опорного леджера и не ближе
15 см к его концам (`LedgerOnLedgerEndClearance`; ближе — это угол у стойки). Один шаг: опорный леджер сам должен быть присоединён к выбранной стойке, узел на любой стойке (в том
числе не выбранной) соединителем не считается, а подсвечиваются только те леджеры и деки, чья нагрузка
реально дошла до выбранных стоек.
Сам UHA распознаётся как мелкая деталь (accessory), а не как леджер. Выключатель: `LedgerOnLedgerEnabled`.
Узел посередине опорного леджера отдаёт нашей стойке половину нагрузки угла дека, то есть 1/8 площади
поля между такими леджерами, а не 1/4.

**Ручное добавление.** «Добавить объекты…» выбирает деки, леджеры или стойки. Добавленное
всегда привязывается к ближайшему леджеру (до 1,5 м), расчёт обновляется сразу при возврате в
диалог, сверху диалога написано, сколько объектов добавлено и сколько из них дают нагрузку.
«Показать в модели» подсвечивает и добавленные вручную объекты.

## Расчётная модель
- Полезная нагрузка: `Q = q(класс) × площадь дека × доля стойки × коэффициент яруса`.
- Постоянная нагрузка `G`:
  - стойки — полный вес всех секций колонны над балкой;
  - леджеры, диагонали, ограждения — по ½ на каждый узел;
  - деки — как и площадь, по пути нагрузки.
- Вес берётся из данных объекта PERI (атрибуты, свойства, XData). Если его там нет —
  из каталога `Catalog` в настройках по артикулу. Если нет и там — по удельным
  значениям `*KgPerM`, и в предупреждениях это отмечается.
- `Fk = Gk + Qk`, `Fd = γG·Gk + γQ·Qk`.

## Как распознаются детали
Модуль работает с **любой балкой и любыми деталями**. Каталог артикулов для этого не нужен.
1. **Правила из настроек** (`Rules`): регулярные выражения по имени блока, атрибутам,
   XData и COM-свойствам. Позволяют явно задать тип для известных объектов.
2. **Форма осевых линий** (`UseShapeRecognition`), если правило не сработало:
   - вертикальные линии — стойка;
   - длинная горизонтальная тонкая деталь высотой до 30 см и шириной до 12 см — леджер (в том числе усиленный, он выше обычного);
   - плоский прямоугольник шириной 150–800 мм — дек;
   - длинная наклонная линия — диагональ;
   - мелочь короче 250 мм (клинья, хомуты, башмаки) не учитывается.

   Для деталей PERI CAD 24 ось берётся из блока `PERI_<артикул>_PartDisplayName_Line`,
   для прочих объектов — из их линий или рёбер габарита. Подробности формата —
   в [`docs/PERICAD24.md`](docs/PERICAD24.md).
3. **Балка** — любой объект, который выбрал пользователь. Её ось — самая длинная
   горизонтальная линия или ребро.

## Настройка распознавания объектов PERI
Как PERI CAD хранит тип, артикул и вес элемента, видно только по реальному чертежу.
Поэтому распознавание вынесено в настройки, перекомпиляция не нужна:
1. В PERI CAD выполнить `PERIDUMP` и выбрать балку, секцию стойки, леджер и дек.
2. Открыть созданный `PERIDUMP_*.txt`: в нём имена блоков, атрибуты, XData и результат
   классификации.
3. Поправить в `BeamCheck.settings.json`:
   - `Rules` — регулярные выражения «текст объекта → тип» (первое совпадение побеждает);
   - `ArticleKeys` / `WeightKeys` — имена свойств с артикулом и весом;
   - `Catalog` — веса по артикулам;
   - допуски `*Tolerance`, если узлы модели смещены относительно осей.

## Сборка
Нужен .NET 8 SDK.
```
dotnet test tests/BeamCheck.Core.Tests                     # тесты расчётного ядра
dotnet build src/BeamCheck.Acad -c Release                 # PERI CAD 24 / AutoCAD
dotnet build src/BeamCheck.Bcad -c Release -f net8.0-windows -p:BricsCADDir="C:\Program Files\Bricsys\BricsCAD V26 en_US"
dotnet build src/BeamCheck.Bcad -c Release -f net48          -p:BricsCADDir="C:\Program Files\Bricsys\BricsCAD V25 en_US"
```
Полный пакет со всеми вариантами собирает `deploy\build.ps1 -BricsCADDir "..."`.
Результат появится в `dist\BeamCheck.bundle`.

## Установка
- Скопировать `dist\BeamCheck.bundle` и `dist\install.ps1` на рабочее место и запустить
  `powershell -ExecutionPolicy Bypass -File install.ps1`.
  - PERI CAD 24 (AutoCAD): bundle ставится в `%APPDATA%\Autodesk\ApplicationPlugins`
    и загружается автоматически: AutoCAD 2021–2024 берёт вариант `net48`, AutoCAD 2025+ — `net8`.
  - BricsCAD: модуль регистрируется на автозагрузку во всех найденных профилях BricsCAD
    (V25 → net48, V26+ → net8).
- Вручную: `NETLOAD` → выбрать нужную DLL.

### «Неизвестная команда PERIDUMP / BEAMLOAD»
Команды появляются только после загрузки DLL. Если модуль загрузился, в командной строке
будет строка `BeamCheck загружен. Команды: …`.
1. Узнайте версию AutoCAD под PERI CAD: команда `ACADVER`.
   - `24.x` (AutoCAD 2021–2024) → `Contents\Acad\net48\BeamCheck.Acad.dll`
   - `25.x` и выше (AutoCAD 2025+) → `Contents\Acad\net8\BeamCheck.Acad.dll`
2. Если файлы скачаны из интернета или почты, Windows их блокирует: ПКМ по DLL →
   «Свойства» → «Разблокировать» (или запустить `install.ps1`, он делает это сам).
3. `NETLOAD` → выбрать DLL из п. 1. Если загрузка не удалась, AutoCAD выведет сообщение
   об ошибке — пришлите его текст.
4. Чтобы модуль загружался сам, положите папку `BeamCheck.bundle` в
   `%APPDATA%\Autodesk\ApplicationPlugins` (это делает `install.ps1`) и перезапустите PERI CAD.

Готовый пакет со всеми вариантами собирает GitHub Actions: вкладка **Actions** → последний
запуск `build` → артефакт **BeamCheck-PERICAD**.
